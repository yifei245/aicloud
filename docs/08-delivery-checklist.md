## 每一步的执行规则

1. 先核对现有代码与报告，复用已有结构，列出该步确实缺少的行为。
2. 实现该步必需的业务和异常处理；完成适当回归，再通过本地网关运行真实单据流程。
3. 报告保存执行时间、测试数据编号、结果和限制；不保存密码、令牌、密钥。验收失败记录原因并修复后重跑。
4. 状态只使用“待完成 / 进行中 / 部分实现，待验收 / 已通过 / 待外部凭据”。只有代码、真实业务结果和必要回归均符合该行标准才标“已通过”。
5. 每步更新本表及 `07-integration-status.md`，再进入下一步；遇到外部凭据依赖可明确登记后继续独立的本地工作。

- 开始：2026-10-17。
- 结果：IM 实际启动就绪；通过网关创建两个独立测试用户、建立好友关系、邀请与接听，使用服务签发令牌接入已部署 LiveKit。
- 双向实收：客户端 1 解码音频 587 帧（有声音 562 帧）、视频 48 帧；客户端 2 解码音频 600 帧（有声音 570 帧）、视频 48 帧。视频按对方发送的颜色及尺寸验证，音频按解码样本能量验证。

- 复验：`python3 scripts/run-local.py start core im` 后，运行 `data/rtc-verifier/bin/python scripts/verify-rtc.py`。独立 Python 环境依赖为 `livekit==1.1.21` 与其依赖；使用生成的音频和视频，不访问摄像头、麦克风。
- 范围：本机后端与 SFU 媒体链路；浏览器/手机真机、外网 NAT/TURN 与正式 HTTPS 部署仍需对应环境验收。本步未修改前端或共享中间件。

## 第 02 步执行记录

- 开始：2026-10-17；进行中，尚未完成库存业务改造或 MES 闭环验收。
- 已定位：`MesWmMaterialStockServiceImpl.validateSelectedStock` 在提交领料明细前读取独立 MES 数量；`MesWmTransactionServiceImpl.createTransaction` 先更新 MES 数量，再请求 WMS。因此 ERP 只向 WMS 入库后，即使 WMS 库存足够，MES 仍可能拒绝领料。
- 接下来按顺序处理：统一库存选择与可用量来源 → 明确批次/库位分配 → 领料/退料/消耗/成品入库和撤销 → 并发、回滚、重复投递 → 从 ERP 入库开始的真实业务验收。
- 不采用直接去掉 MES 数量校验或允许本地负库存的办法绕过问题，避免丢失批次追溯和库位约束。
