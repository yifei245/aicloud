# 业务集成设计与实施（2026-10-13）

本设计的数据归属及新增本地 LiveKit 已获用户确认。仅修改后端、SQL、运行配置和文档；复用本地 MySQL、Redis、Nacos、XXL-Job Admin。保留 `05-gap-list.md` 原审查记录，完成情况另行记录。

## 数据归属

| 业务数据 | 主系统 | 其他模块的职责 |
|---|---|---|
| 商品、物料基础档案及基本单位 | ERP | 商城维护销售展示、渠道价格和促销；WMS 保存仓储 SKU；MES 保存 BOM、工艺和生产属性，均关联 ERP 商品 |
| 实物库存、预占、出入库流水 | WMS | 商城下单预占，取消释放，发货扣实物；ERP 采购/销售审批、MES 领料/成品入库调用 WMS，不再独立决定可用库存 |
| 生产事实 | MES | 维护生产、领料和产出单据；库存变化交给 WMS |
| 员工档案、任职状态、假期及考勤 | HRM | OA 负责申请；BPM 负责审批；审批结果更新 HRM，OA 原记录保留作为历史，不再重复生成独立考勤事实 |
| 客户合同及签约事实 | CRM | 合同审批通过后创建关联 ERP 销售单；按商品映射转换明细；重复回调不重复建单 |
| 业务记账凭证 | FMS | ERP 收付款、商城业务、薪资及报销提交凭证来源；按账套规则生成待审核凭证，财务审核后入账 |

已有数据不自动合并或覆盖。先建立明确的商品、仓库、员工和账套映射；缺少映射时返回可定位的错误或保留待处理集成记录，不能静默产生第二套有效库存。计量单位不一致时拒绝自动换算；金额统一明确分/元转换，并校验借贷平衡。

## 一致性与失败处理

复用现有 Service、MyBatis Plus、Feign 和内部 RPC 鉴权。商品及仓库映射、库存预占、凭证来源、业务集成待处理记录使用必要的独立表。各服务仅通过目标服务 API 操作目标业务数据；不通过共享数据库直接修改其他模块业务表。

库存预占必须在订单接受前同步完成，并通过数据库行锁校验库存。普通出入库、员工状态、财务来源和合同转销售单采用与源业务事务一起保存的待处理记录，提交后投递。目标接口按来源业务键幂等；失败可重试、可查询、可人工重放。订单创建回滚时释放预占，并提供故障补偿；业务取消或反审核产生明确的冲回操作，不能通过删除账务/库存历史代替冲回。

财务默认仅生成草稿，保留来源模块、单据编号、账套及明细。已审核凭证不能被后台重试直接覆盖或删除；后续业务撤销须进入冲销处理。不得自动替用户做税务假设。

## 实施顺序与验收

1. BPM 待办、通过、驳回、超时始终生成站内信；短信成为可选附加通道。关闭或故障的短信不能阻断站内信或审批提交。WebSocket 使用已有 Redis 广播，通过两个实例验证跨实例投递。
2. 启用 XSS 防护并校验公告、跟进、聊天等持久化文本；流程 XML、表单 JSON和外部签名回调等协议内容采用精确例外及独立校验，避免全模块绕过。恢复已确认缺失的业务任务调度，防止订单、预占、支付通知和人员变动不推进。
3. ERP 主数据关联 WMS、MES、商城；验收采购入库、商城预占/取消/发货、MES 领料/产出，以及重复请求、库存不足和源事务回滚。
4. FMS 接入业务来源；验收收付款、商城收入/退款、薪资、报销的待审核凭证与重复回调保护。
5. OA 审批更新 HRM 任职状态、假期和考勤；CRM 审批生成 ERP 销售单。验证回调重放、缺少映射和失败恢复。
6. 增加员工手机专用接口，复用员工管理身份和原业务权限，提供本人审批、申请、通知、档案、打卡、假期及工资条；与会员身份保持隔离。
7. 开放 API 增加商品、库存、订单和业务查询，使用独立应用身份、精确 scope、租户及必要的应用授权范围；不得借由开放 API 绕过管理权限或暴露完整员工隐私。
8. 提供后端报表/打印模板管理、设计数据保存、参数化数据查询、预览及导出，复用现有查询隔离和文档工具；不恢复不符合当前协议约定的积木依赖，不开发前端设计器。
9. 按已获得授权部署一个独立、保留的本地 LiveKit，配置真实随机密钥，验证音视频令牌、房间及回调。证明媒体可连接后才能标为完成，不能只以签发 JWT 代替验收。

所有结果使用真实本地 HTTP/数据库和有业务意义的回归测试。记录完成与未完成项，不以接口数量、目录存在或模拟成功响应宣称业务已打通。
