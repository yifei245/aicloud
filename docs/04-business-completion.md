# 业务补齐设计与验收

## 交付标准

服务启动、空表查询和 OpenAPI 路径数量只能证明基础集成。一个业务功能必须具备必要配置、真实写入、状态流转、关联数据更新、权限校验和结果读取，才能计入业务完成。已有源码优先复用，不新增重复业务框架。

## OA 核查结果与实施顺序

OA 已迁移业务服务、数据库和接口，但原验收没有执行 OA 写入和审批，遗漏了以下必要环节：

1. 提供真实登录的业务初始化入口，导入并发布 14 个 OA 流程。保留已存在的自定义模型，不覆盖、不重复发布；确认部门负责人，使默认流程不会因候选人为空而自动通过。
2. 修复 BPM 到 OA/CRM 的内部回调凭据、租户传递和错误检测。内部凭据只发往固定内部 RPC 地址；不得写进日志或发送至用户配置的外部通知地址。
3. 补齐站内信模板与本地定时提醒，不要求安装新的调度中间件。
4. 通过真实网关执行请假、加班、转正、离职、报销、出差及报销、用品领用和归还、会议室、用印、用车和还车、公文收发。
5. 验收公告阅读、日程、计划、工作报告、任务、通讯录、便签、讨论投票、云盘权限与回收站等协同办公操作。
6. 执行已有 OA 单测，修复失败；补充跨服务回调与重复事件回归。邮箱本地账户、文件夹与草稿验收；真实 IMAP/SMTP 等待用户配置自己的账号。

## 其他模块

ERP、CRM、BPM、报表、IoT 已有关键业务流验证记录，其余模块的写入和跨服务状态流转尚不能称为完整验收。继续逐模块检查现有实现与必要种子数据，发现空实现或断开的业务链路后补齐并记录实际运行结果。外部凭据延期不等于本地业务可以缺失。

## Knife4j 空分组修复

已复现 `/admin-api/hrm/v3/api-docs` 返回 503：网关静态列出了全部业务分组，但原本的默认启动只运行 system、infra、member、gateway，未启动的服务没有 Nacos 实例。报表服务还遗漏了文档聚合配置。验收脚本原本在结束时无条件停用对应业务服务，也会让已经打开的分组再次变空。

1. 补齐报表文档分组。网关文档必须覆盖全部 22 个 HTTP 业务服务；网关本身和 MQTT 协议网关不作为业务接口分组。
2. 本地默认启动完整组合，保留显式 `core` 和模块名用于裁剪。按依赖顺序启动并等待健康状态，失败时指出服务与日志路径，不把“进程已创建”当作启动成功。
3. 验收脚本只停止自身新启动的应用，保留用户已经运行的服务。共享中间件始终复用。
4. 通过网关逐个读取 Knife4j 实际配置中的文档地址，验证 OpenAPI 格式、接口数量和分组覆盖率；失败必须返回非零退出状态。浏览器切换业务分组，确认接口目录可见。

文档验收证明接口可见和可调试，业务是否可用仍需按前述写入与状态流转标准验收。

## 财务初始化补齐

财务报表模板和默认科目原本没有包含在完整初始化 SQL，导致新账套无法正常初始化或报表缺少行。新增幂等科目种子和报表模板脚本，保留已有同编码科目和自定义公式。基础科目依据[财政部《小企业会计准则》附录](https://kjs.mof.gov.cn/zhengcefabu/201111/P020111118325852734144.pdf)，明细科目为项目模板的默认设置。

更正两项默认结账模板：提现金使用库存现金借方、银行存款贷方；业务招待费报销使用管理费用明细借方、库存现金贷方。仅影响新初始化的模板，不覆盖已有账套定制。验收通过真实网关新建带验证标记的账套、初始化科目与结账模板、读取三类财务报表，并验证重复初始化被拒绝。账套及其审计数据保留用于复查。

## 验收证据

每次验证仅访问本地网关和本地数据库。记录功能名称、断言和通过/失败结果，不记录令牌、密钥或密码。只清理验证脚本自己创建且允许删除的记录，保留必要的审批、库存和协作历史。结果以执行后的 JSON 报告为准。
